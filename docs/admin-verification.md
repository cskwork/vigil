# 관리 콘솔 검증 기록

2026-09-15, macOS arm64 로컬 Chromium에서 v0.6.0 변경을 검증했습니다.

## 기능 검증

| 범위 | 확인 결과 |
|---|---|
| 프로젝트·사이트 관리 | UI에서 프로젝트 생성, 사이트 추가, 이름과 URL 수정, 기본 사이트 선택을 확인했습니다. ID와 URL 호스트는 자동 설정됩니다. |
| 저장 유지 | 서버를 재시작한 뒤 프로젝트 두 개와 사이트 설정, 저장된 검사·캡처를 다시 확인했습니다. 자연어 요청의 12단계 결과 집계와 스크린샷도 재시작 후 동일하게 복원됐습니다. |
| 프로젝트 분리 | 다른 프로젝트의 검사 목록이 섞이지 않고, 검색·새로고침·페이지 이동 후 선택이 유지됐습니다. 자동 테스트에서는 동일한 검사 ID를 두 프로젝트에 각각 등록했습니다. |
| 자유서술 시나리오 | UI에서 네이버 검색 흐름을 입력해 Claude Opus 5 medium 에이전트가 12단계 DSL을 생성했습니다. 별도 Chromium 실행이 입력·Enter 제출·결과 URL·검색어 유지 조건을 모두 통과했습니다. |
| 네이버 | 메인 검색 입력창 표시와 OpenAI 검색 시나리오의 실제 실행이 PASS였습니다. 최초 Vigil 버튼 클릭 요청은 에이전트가 기대 동작을 observation으로 분류해 확인 필요로 남았고, 이후 프롬프트를 보완했습니다. 두 요청은 별개이며 최초 요청을 통과로 바꾸지 않았습니다. 네이버 전체 서비스나 로그인 흐름은 검증하지 않았습니다. |
| URL 반영 | 사이트 URL의 query를 수정하고 기존 검사를 다시 실행해, 변경된 전체 URL이 실행 대상에 반영되고 PASS인 것을 확인했습니다. |
| 진행 피드백 | 실행 직후 에이전트 연결·탐색 상태와 최신 탐색 캡처가 표시됐습니다. 독립 실행 단계와 완료 캡처도 같은 패널에 나타났습니다. |
| 실패 피드백 | 수동 YAML의 실패 조건을 검사해 기대 동작 불일치로 판정하고 “화면에 해당 문구가 보여야 하는데 보이지 않습니다”라고 안내했습니다. |
| 화면 캡처 | 실행 패널, 결과 목록과 검사 상세에서 이미지가 표시되고 확대 대화상자가 열렸습니다. 완료 시 단계 목록은 접혀 있습니다. |
| 승인 | 실행이 통과한 검사를 UI에서 승인하고 정식 검사 상태로 전환됨을 확인했습니다. admin 모드에서는 자동 일정 실행을 시작하지 않습니다. |

초기 제한된 실행 환경에서는 Chromium 시작이 실패해 ENV_FAILURE로 기록됐습니다. 브라우저를 실행할 수 있는 권한으로 서버를 다시 시작한 뒤 실제 검사는 통과했습니다. 처음 실패한 기록은 과거 실행 이력으로 보존했습니다.

## 자동 검사

- `go test ./...` 통과.
- `go vet ./...` 통과.
- `go test -race ./internal/admin ./internal/ui ./cmd/vigil` 통과.
- 공통 및 인라인 JavaScript 구문 검사 통과.
- 여러 후보 중 일부 실패, 이전 실행의 통과 결과, 중복 스크립트를 전체 통과로 오인하지 않는지 검증했습니다. 저장된 결과 집계의 복원도 확인했습니다.
- 자유서술 요청의 기대 동작 실패는 승인 대기로 보존하고 자동 수정을 시도하지 않습니다. 검사 스크립트 자체를 보완한 경우에도 승인 없이 정기 실행에 들어가지 않는지 검증했습니다.
- 프로젝트 저장 실패, 동시 편집 revision 충돌, 실행 중 URL 수정, 잘못된 URL, 교차 출처 요청과 프로젝트 간 실행 조회 거부를 검증했습니다.
- 배포 식별자가 없거나 승인 대기 중인 수동 검사가 결과 화면에서 사라지는 문제를 회귀 테스트로 재현한 뒤 수정했습니다. 사이트별 결과가 따로 표시되는 것도 확인했습니다.

## 별도 검토

관리 화면과 프로젝트 격리의 첫 검토는 Claude Opus 5 medium으로 수행했습니다. 자유서술 생성·검증 흐름은 이후 추가됐으므로 첫 검토와 구분합니다. 최종 변경은 호스트가 코드와 실행 증거를 직접 대조했습니다. 전체 테스트·정적 검사·경쟁 상태 검사와 실제 브라우저 검증을 통과했습니다.

다중 사용자로 확대할 경우 전역 요청 잠금의 처리량을 재검토하는 것이 좋습니다. 현재는 로컬 단일 운영자를 전제로 합니다. admin은 요청한 작업과 해당 스크립트 보완만 처리하며 정기 worker를 시작하지 않습니다. 제외된 검사의 과거 결과는 이력을 보존하기 위해 결과 화면에 남습니다.
