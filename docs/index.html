vigil은 계속 지켜봅니다.

vigil watches your repo for shipped features, waits until the deployment actually serves them, then drives real browsers through deterministic YAML scenarios — and files evidence for every run. Give it one URL and it grows its own coverage. vigil은 저장소에서 배포된 기능을 감지하고, 그 리비전이 실제로 서비스될 때까지 기다린 뒤, 결정적 YAML 시나리오로 실제 브라우저를 구동합니다. 모든 실행의 증거를 남기고, URL 하나만 주면 커버리지를 스스로 넓혀 갑니다.

Pipeline파이프라인

From commit to evidence, without a human in the loop커밋에서 증거까지, 사람 손 없이

Five deterministic stages. Each one runs on its own, every time.다섯 단계가 매번 같은 방식으로, 스스로 돌아갑니다.

01

Watch the repo저장소 감시

Detects shipped features and groups commits by issue key.배포된 기능을 감지하고 커밋을 이슈 키 단위로 묶습니다.

02

Gate on the deploy배포 게이트

Waits until the deployment actually serves that revision (asset-version gate).해당 리비전이 실제로 서비스될 때까지 대기합니다(에셋 버전 게이트).

03

Drive real browsers실제 브라우저 구동

Deterministic YAML scenarios — Lightpanda for fast headless runs, Chromium to confirm ambiguity or capture real-render evidence.결정적 YAML 시나리오 — 빠른 헤드리스는 Lightpanda, 모호한 결과 확인과 실제 렌더 증거는 Chromium.

04

File evidence증거 기록

Console, network, DOM, screenshots on every run. Failures become reproducible incident reports.매 실행마다 콘솔·네트워크·DOM·스크린샷. 실패는 재현 가능한 인시던트 리포트가 됩니다.

05

Re-check promises약속 재점검

Scenarios are promises the service must keep, re-checked on a cadence.시나리오는 서비스가 지켜야 할 약속. 주기적으로 다시 검증합니다.

Autonomy자율 커버리지

Give it one URLURL 하나면 됩니다

A supervisor loop — any pi-compatible model, default zai/glm-5.3-flash — reads the QA state every 15 minutes and decides where coverage is missing. The model only proposes; deterministic code validates every action before it becomes a job.슈퍼바이저 루프(pi 호환 모델 아무거나, 기본은 zai/glm-5.3-flash)가 15분마다 QA 상태를 읽고 커버리지가 빈 곳을 판단합니다. 모델은 제안만 하고, 모든 행동은 결정적 코드의 검증을 통과해야 작업이 됩니다.

  • Six verbs, nothing else. discover_route, repair_script, validate_candidate, run_scenario, raise_cadence, quarantine. Deletion verbs are refused by name — the supervisor can never remove coverage.허용된 동사는 여섯 개뿐. discover_route, repair_script, validate_candidate, run_scenario, raise_cadence, quarantine. 삭제 동사는 이름부터 거부됩니다 — 슈퍼바이저는 커버리지를 절대 지울 수 없습니다.
  • The route map fills itself in from wherever browsers actually go; /user/42 collapses to /user/:id.라우트 맵은 브라우저가 실제로 간 곳에서 스스로 채워집니다. /user/42는 /user/:id로 접힙니다.
  • Realistic, but pinned. Discovered scenarios use a configured test identity and can fill forms with realistic data. Mutation levels: read-only / reversible; destructive stays behind policy.현실적이지만 고정된 신원. 발견된 시나리오는 설정된 테스트 계정을 사용하고, 폼을 현실적인 데이터로 채울 수 있습니다. 변이 수준은 read-only / reversible, destructive는 정책 뒤에 있습니다.
  • Self-repair before humans. A failing scenario gets bounded agent repair (default configurable, e.g. 3 attempts) before a person ever sees it.사람보다 자가 수리가 먼저. 실패한 시나리오는 사람에게 오기 전에 횟수 제한이 있는 에이전트 수리(기본값 설정 가능, 예: 3회)를 거칩니다.
  • Watch it live. The dashboard (Korean UI, served by vigil loop --ui) shows verification results, running jobs, AI assistant activity, the coverage-growth panel, and the schedule window control in real time.실시간 대시보드. vigil loop --ui로 뜨는 한국어 대시보드에서 검증 결과, 실행 중인 작업, AI 어시스턴트 활동, 커버리지 성장 패널, 스케줄 창 제어를 실시간으로 봅니다.

Safety rails안전장치

The model proposes. Code decides.모델은 제안하고, 코드가 결정합니다.

Hard limits that hold no matter what the model says.모델이 뭐라고 하든 지켜지는 하드 리밋.

Rail장치 Guarantee보장 내용
rule 12 A model outage never stops deterministic QA. Scheduled scenarios keep running.모델 장애가 결정적 QA를 멈추지 못합니다. 예약된 시나리오는 계속 돕니다.
verb allowlist Six verbs only; deletion verbs are refused by name. Coverage can grow, never be removed by the supervisor.동사는 여섯 개뿐, 삭제 동사는 이름만으로 거부. 커버리지는 늘 수만 있고 슈퍼바이저가 지울 수는 없습니다.
host allowlist Browsers only reach hosts you listed. Nothing wanders off-target.브라우저는 허용된 호스트만 접근합니다. 대상 밖으로 나가지 않습니다.
task budgets Hourly task budgets cap how much work the loop can queue.시간당 작업 예산으로 루프가 쌓을 수 있는 작업량을 제한합니다.
active hours Weekly active-hours window (e.g. weekdays 08:00–19:00), editable from the live dashboard.주간 활동 시간 창(예: 평일 08:00–19:00), 라이브 대시보드에서 바로 수정할 수 있습니다.
mutation policy Discovered scenarios run read-only or reversible; destructive actions stay behind policy.발견된 시나리오는 read-only 또는 reversible로만 실행되고, destructive는 정책 뒤에 남습니다.
bounded repair Self-repair is capped (default configurable, e.g. 3 attempts) before escalating to a human.자가 수리 횟수에 상한이 있고(기본값 설정 가능, 예: 3회) 넘으면 사람에게 넘깁니다.
Quickstart빠른 시작

Running in five commands명령 다섯 줄이면 켜집니다

Build the Go binary, fetch the browser, point it at your deployed app.Go 바이너리를 빌드하고, 브라우저를 받고, 배포된 앱을 가리키면 끝.

$ git clone https://github.com/cskwork/vigil
$ cd vigil && go build ./cmd/vigil
$ ./vigil doctor --install        # fetches the Lightpanda browser
$ cp vigil.example.yaml vigil.yaml   # point target.base_url at your deployed app
$ ./vigil loop --ui 127.0.0.1:8787

Then open 127.0.0.1:8787 — the live board shows verification results, running jobs, and the coverage-growth panel.이후 127.0.0.1:8787을 열면 검증 결과, 실행 중인 작업, 커버리지 성장 패널이 보이는 라이브 보드가 있습니다.
