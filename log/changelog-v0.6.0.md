# v0.6.0 — 프로젝트별 검증 관리 콘솔

## 변경 사항

- 기획·QA 담당자가 처리할 일과 검증 결과를 확인하는 업무용 관리 화면으로 개편했습니다.
- `vigil admin`에서 프로젝트와 여러 사이트를 등록하고 URL 및 기본 사이트를 변경할 수 있습니다. 설정은 재시작 후에도 유지됩니다.
- 새 프로젝트의 스크립트, 실행 이력, 증거를 분리합니다. 검색·필터·화면 이동·캡처 링크가 선택한 프로젝트를 유지합니다.
- 버그 재현 시나리오, 기능 설명, 커밋 메시지·변경 내용을 자유롭게 입력하면 에이전트가 E2E 스크립트를 작성하고 독립 실행합니다. 프로젝트·사이트 ID, URL 호스트와 Chromium 기본값을 자동으로 설정합니다. YAML 및 추가 설정은 고급 메뉴에서 사용합니다.
- 실행 직후 실제 진행 상태를 보여 주고 완료 캡처를 같은 화면에 표시합니다. 결과 목록과 검사 상세에서 캡처 확대 팝업을 사용할 수 있습니다.
- 배포 식별자가 없는 수동 검사와 승인 대기 중인 검사의 실제 결과도 표시합니다. 같은 검사를 여러 사이트에서 실행한 결과를 구분합니다.
- 실행 중 URL 변경과 오래된 설정 덮어쓰기를 거부합니다. 브라우저는 실행 종료 후 정리합니다.

## 호환성과 범위

`admin`은 로컬 loopback에서 사용하는 수동 실행 콘솔입니다. 요청한 시나리오에 한해 에이전트가 탐색·작성·검증합니다. 대상 서비스 코드는 수정하지 않으며 정기 실행과 Jira 알림은 자동 시작하지 않습니다. 기존 `loop --ui`, `serve`, `proof` 명령을 유지합니다. 관리자 설정은 기존 YAML과 별도의 레지스트리에 저장됩니다. 기존 데이터베이스를 파괴적으로 변경하지 않습니다.

DSL의 `goto: "#"`는 선택한 사이트 URL의 경로와 query를 보존합니다. 복합 시나리오를 자연어로 요청하거나 기존 YAML DSL로 등록할 수 있습니다.

## 검증

- 전체 Go 테스트와 `go vet ./...`.
- 관리 콘솔, UI와 실행 처리 경로의 race 검사.
- 실제 브라우저에서 프로젝트 생성, URL 수정·사이트 추가, 스크립트 등록, 자유서술 시나리오 요청, 프로젝트 전환·검색, 네이버 실행과 화면 캡처 확대를 확인했습니다.

자세한 설정과 사용 범위는 [관리 콘솔 안내](../docs/admin-console.md)를 참고하세요.
